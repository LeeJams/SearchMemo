# MemoFind 단일 메모 라이브러리 SDD

## 목표

MemoFind의 홈을 하나의 메모 라이브러리로 단순화한다. 메모와 프롬프트를
별도 탭으로 분리하지 않고 폴더로 정리하며, 긴 메모는 Apple Notes처럼
목록에서 짧게 미리 보고 상세 화면에서 전체 내용을 읽고 편집한다.

## 제품 벤치마크

- 저장된 모든 콘텐츠는 하나의 메모 목록에서 검색할 수 있어야 한다.
- 폴더는 메모를 삭제하지 않고 정리하는 수단이어야 한다.
- 목록은 제목, 짧은 본문 미리보기, 수정일만 보여 빠르게 훑을 수 있어야 한다.
- 긴 내용은 목록 높이를 늘리지 않고 말줄임표로 표시하며, 항목을 누르면
  선택 가능한 전체 본문을 보여준다.
- 첫 줄을 제목처럼 사용하는 Apple Notes의 작성 모델을 따른다.

## 정보 구조

### 홈

- `메모 / 프롬프트` 세그먼트 탭을 제거한다.
- 별도 `MemoFind` 제목 헤더를 표시하지 않는다.
- 상단 안전영역 아래에 44dp 높이의 검색창을 배치한다.
- 검색창 아래에 가로 폴더 필터를 배치한다.
- 검색창·폴더 필터·메모 목록의 세로 간격은 12dp 기준으로 맞춘다.
- 기본 필터:
  - `전체`: 모든 메모
  - `메모`: 폴더가 지정되지 않은 메모
  - `프롬프트`: 3.1.0 프롬프트 데이터가 변환된 경우에만 표시
- 사용자는 폴더를 생성·이름 변경·삭제할 수 있다.
- 폴더 삭제 시 포함된 메모는 삭제하지 않고 `메모`로 이동한다.
- 새 메모는 현재 선택한 폴더에 저장한다. `전체`에서는 `메모`에 저장한다.
- 화면 오른쪽 아래에는 `설정 / 메모 작성` 순서의 플로팅 액션을 나란히
  배치한다.

### 메모 카드

- 오른쪽 화살표를 표시하지 않는다.
- 첫 번째 비어 있지 않은 줄은 제목 스타일로 강조하되 메모 전체를 하나의
  텍스트 블록으로 렌더링한다.
- 줄바꿈이 없는 긴 메모를 포함해 메모 내용은 카드에서 최대 3줄까지
  표시하고 넘치는 내용은 말줄임표로 처리한다.
- 수정일을 표시한다.
- 카드를 누르면 액션 메뉴가 아니라 메모 상세 화면을 연다.

### 메모 상세 및 편집

- 상세 화면은 모달이 아니라 네이티브 스택의 페이지(`MemoDetail` 라우트)로
  열고 본문을 스크롤·선택할 수 있게 한다.
- iOS에서는 화면 어디서나 오른쪽으로 스와이프해 홈으로 돌아갈 수 있어야
  한다(`gestureEnabled`, `fullScreenGestureEnabled`). Android는 하드웨어
  뒤로 가기로 동일하게 동작한다.
- 상세 하단은 `삭제 / 수정 / 복사 / 검색` 순서의 동일한 너비 4칸 작업
  모음으로 구성한다.
- 하단에 수정 작업이 있으므로 헤더에는 중복 수정 버튼을 표시하지 않는다.
- `검색` 시트는 상세 화면을 닫지 않고 그 위에 표시하며, 상세 페이지의
  자식으로 렌더링해 iOS에서 올바른 화면 컨트롤러가 시트를 제시하게 한다.
- 검색 시트는 검색 아이콘과 `검색 서비스` 제목, 검색 서비스 그리드만
  표시하며 복사·수정·삭제 같은 메모 작업은 표시하지 않는다.
- 검색 서비스는 행마다 동일한 `flex: 1` 너비의 3열로 구성하고, 좌우
  12dp·열 사이 8dp 간격을 사용한다. 마지막 행이 3개 미만이면 빈 열을
  채워 iOS와 Android에서 전체 그리드가 동일하게 중앙 정렬되어야 한다.
- 작업 시트를 닫거나 뒤로 가면 상세 화면의 기존 스크롤 위치와 내용이
  그대로 유지되어야 한다.
- 수정 화면은 상세 페이지 위에 모달로 열리며, 저장 후에는 갱신된 내용의
  상세 페이지로 돌아온다. 삭제한 경우에만 상세 페이지를 닫는다.
- 편집 화면은 최대 20,000자를 지원한다.
- 편집 화면에서 저장할 폴더를 선택할 수 있다.
- 편집 하단은 한 줄 도구 모음으로 구성하며 폴더 선택은 왼쪽 가로 스크롤,
  색상 팔레트 버튼은 오른쪽 끝의 최소 44×44dp 고정 영역에 배치한다.
- 선택 가능한 색상을 하단에 항상 펼쳐두지 않는다. 팔레트 버튼은 현재
  색상을 표시하고, 누르면 도구 모음 위에 작은 팔레트 팝오버를 연다.
- 팔레트에서 색상을 선택하면 메모 색상에 즉시 반영하고 팝오버를 닫는다.
  편집 화면을 다시 열면 저장된 색상이 선택되어야 한다.
- 취소·저장·닫기 버튼은 iOS/Android의 상단 및 하단 안전영역 안에 있어야 한다.

### 검색 서비스

- 기존 검색 서비스는 유지하고, 선택 가능한 서비스에 Brave Search,
  Google Scholar, Semantic Scholar, Microsoft Copilot, DeepSeek를 추가한다.
- ChatGPT와 Grok은 각각 공식 기본 주소인 `https://chatgpt.com`,
  `https://grok.com`을 사용하고 브랜드 표기는 `YouTube`로 통일한다.
- Copilot과 DeepSeek를 포함한 AI 서비스는 메모 전체를 클립보드에 복사한
  다음 서비스 홈을 열며, 본문을 URL 쿼리에 포함하지 않는다.
- 일반·학술 검색은 메모를 UTF-8 URL 쿼리로 인코딩하되 완성된 URL이
  1,900자를 넘지 않도록 코드포인트 경계에서 안전하게 자른다.
- 새 서비스는 설정 목록에만 추가하고 기존 사용자의 기본 선택 6개는
  변경하지 않는다.
- 서비스 키, HTTPS URL, 아이콘 매핑, 한글·특수문자 인코딩, 긴 메모 절단,
  AI 전체 복사 계획을 순수 모델 테스트로 검증한다.

## 데이터 모델

### 메모 스키마 v3

- 기존 필드 유지
- `folderId: string | null` 추가
- 텍스트는 앞뒤 공백을 제거하고 최대 20,000자로 제한
- 기존 v1/v2 메모는 `folderId: null`로 마이그레이션

### 폴더 스키마 v1

- 별도 로컬 저장 키 사용
- 필드: `schemaVersion`, `id`, `name`, `createdAt`, `updatedAt`
- 이름은 앞뒤 공백 제거, 대소문자를 무시해 중복 방지
- 폴더 삭제는 메모 삭제를 유발하지 않는다.

### 기존 프롬프트 마이그레이션

- 프롬프트 본문을 메모 텍스트로 변환한다.
- 명시적 제목이 본문 첫 줄과 다르면 `제목 + 빈 줄 + 본문`으로 변환한다.
- 태그·즐겨찾기·생성일·수정일을 유지한다.
- ID는 `prompt:<기존 ID>`로 변환해 재실행해도 중복되지 않게 한다.
- 메모 저장이 성공한 뒤에만 기존 프롬프트 저장소를 비운다.

## 반응형 언어 및 안전영역

- 언어 변경 컨텍스트를 홈과 설정 UI가 직접 구독해 저장 직후 전체 화면이
  선택한 언어로 다시 렌더링되어야 한다.
- 앱 루트에 `SafeAreaProvider`를 두고 스택의 각 페이지는 `SafeAreaView`로
  상·하단을 보호한다. 자체 창을 갖는 React Native `Modal`(편집 화면 등)은
  내부에 `SafeAreaProvider`를 한 번 더 둔다.
- 상단 취소·저장·닫기 버튼의 최소 터치 영역은 44×44pt/dp이다.

## 백업

- 폴더를 포함하는 백업 v2를 내보낸다.
- 기존 백업 v1은 `folders: []`로 읽어 계속 복원할 수 있어야 한다.
- 동일 ID의 폴더는 더 최신 `updatedAt` 항목을 유지한다.
- 손상된 메모·프롬프트·폴더가 하나라도 있으면 전체 복원을 거부한다.

## 수용 기준

1. 언어 선택 즉시 홈과 열린 설정 화면의 문구가 바뀐다.
2. API 36 에뮬레이터에서 검색 설정의 저장 버튼이 StatusBar 아래에 있고
   실제 탭으로 저장된다.
3. 홈에는 라이브러리 전환 탭이 없고 폴더 필터만 있다.
4. 20,000자 메모가 저장·수정·백업·복원된다.
5. 줄바꿈 유무와 관계없이 긴 메모 카드가 3줄에서 말줄임되고, 탭하면
   전체 본문이 열린다.
6. 메모 카드에 오른쪽 화살표가 없다.
7. 폴더 생성·이름 변경·삭제·메모 이동이 데이터 손실 없이 동작한다.
8. 기존 프롬프트가 프롬프트 폴더의 메모로 한 번만 변환된다.
9. 상세 하단에 `삭제 / 수정 / 복사 / 검색`이 동일한 4칸으로 표시되고,
   검색 시트에는 검색 서비스만 표시된다.
10. 검색 시트를 열고 닫아도 상세 화면이 내려가지 않고 같은 메모를 계속
    보여준다.
11. 검색 설정에서 신규 검색·AI 서비스를 선택할 수 있고, 긴 메모의 일반
    검색 URL은 1,900자를 넘지 않으며 AI에는 전체 메모가 복사된다.
12. 단위 테스트, Expo 의존성 검사, Expo Doctor, Android/iOS Hermes 번들이
   모두 성공한다.
